## 五句填空公式（全片核心）

1. **这个 skill 是什么、干什么用**
2. **工作流程**（一步步怎么走，越具体越好）
3. **触发条件**（当我说什么的时候自动调用）
4. **参考示例**（给样例图 / 样例效果，想模仿别人就给样例）
5. **名字**

**原话**：「你做几个填空题就可以把 skill 做好。」
**进阶提示**：「如果说你设计的 skill 工作流程比较复杂，比如第一步要干这个、第二步要干那个、第三步要干那个，你就给它描述清楚就可以。」

## 迭代闭环（最值得抄的部分）

```
提需求 → 看产出 → 不满意就提修改意见 → 满意
                                        ↓
                        「把新的修改更新到 skill」
                                        ↓
                          下次自动按新标准工作
```

**关键动作是最后那句**。不说这句，改的只是这次的结果；说了，改的是**以后所有次**。

## 三个容易漏的操作细节

1. **装完必须重启 Codex**（原文：「每当我们安装好一个新的 skill 之后，我们要重启一下 Codex，确保它能把这个 skill 顺利加载」）
2. **验证安装成功**：新建对话说「我想创建一个 skill」，看它回不回「我会先按 skillcurator 这个说明来处理」
3. **名字不支持下划线**（视频里 auto 帮他把 `大量_封面` 改成了驼峰/纯字母）

## 一句话收尾（原话）

> 「单人做 skill 这件事其实并不难，真正难的是你如何把工作流程想清楚、跟 AI 说清楚，以及每个环节的标准要跟 AI 表达清楚。」

**这句话就是 ink-horizon 存在的理由。** 这条 skill 里每一条规矩背后都是一次被否、一次白改，或者一次删了找不回来的东西——把它们写下来，就是让下一次不用重走。

## 与本 skill 的关系

这条视频给的是**怎么写 skill** 的方法论；`ink-horizon` 是**用它写出来的那个 skill 本身**。
要扩展 ink-horizon（加新段落模板、加新平台、加新的自评指标），就照五句公式补：
- 新功能是什么 → 写进第 3 或第 6 节
- 新的触发词 → 加到第 0 节
- 新的踩坑 → 加到第 7 节（**必须带实测数字**，不要写「注意性能」这种废话）
